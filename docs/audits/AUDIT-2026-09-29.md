## Summary

A full audit of `main` at `3211086` (same commit as tag `v0.4.0`), done on 2026-09-29. It used the SigmaReview passes (correctness, security, release, tests), the SigmaRefactor scan, and a SigmaImprove pass over docs and tooling. Every finding below was reproduced or re-read in the source before it went into this issue. Items that failed that check were dropped.

Baseline: `npm test` passes, with 416 tests in about 30 s. The published npm version is `0.4.0`. The package has no runtime dependencies, so `npm outdated` and `npm audit` have nothing to report.

Evidence classes: **M1** = reproduced with a script in a temp project. **M2** = certain from the source. Priorities use the SigmaReview scale (P1 = a main journey is broken or unsafe, P2 = material but bounded, P3 = small).

Repro scripts for the M1 installer findings use `runCli` from `src/cli.js` with a temp project and a temp `HOME`/`USERPROFILE`. Each finding describes its trigger, so a fixer can rebuild the script as a test.

## A. Installer defects (src/)

### A1. P1 · M1: install, uninstall, and restore overwrite another tool's `skills-lock.json`
- **Where:** `src/project-lock.js:37-40`, `:52`, `:98`. `inspectProjectLock` returns kind `generic` plus an empty Sigma lock, and `loadProjectLock` drops the kind. The writers do not check it: `src/transaction.js:145,494,617-621`, `src/uninstall.js:547-548`, `src/restore.js:467-468`. Only `purge` checks it (`src/purge.js:236`).
- **Trigger:** a project that uses `npx skills` (vercel-labs/skills) has `skills-lock.json` = `{"version":1,"skills":{"acme-skill":{...}}}`. Run `sigmaskills install sigmawrite`.
- **Result:** the file becomes `{schemaVersion:1, release, skills:{sigmawrite}}`, and `acme-skill` is gone. This is a common setup, because `npx skills` writes this exact file name. This repo has one too.
- **Fix:** in every write path, refuse to write, or keep the foreign entries, when the kind is `generic`. Pick one way and document it.

### A2. P2 · M1: recorded destinations in state and journals are not confined to the root, so a crafted state file can delete folders outside the project
- **Where:** `path.resolve(root, ...rel.split('/'))` has no containment check in `src/uninstall.js:106,124`, `src/restore.js:118,309`, `src/purge.js` (journal `items[].absolutePath`, `:20-45`, `:164-199`), and `src/status.js:207-219`. `validateManagedState` (`src/state.js:238`) checks only types.
- **Trigger:** a repository commits `.agents/.sigmaskills/state.json` (with `git add -f`) where `destination` is `../victim`. The user runs `sigmaskills uninstall --all --yes`.
- **Result:** `../victim` is removed, and the output says `Outcome: removed`.
- **Fix:** when state and journals load, check every recorded path with `resolveSkillPath`, `resolveGlobalSkillPath`, or a state-dir check. Reject a path that escapes.

### A3. P2 · M1: `restore` deletes an unowned folder at a host destination
- **Where:** `src/restore.js:304-320` (`applyOwnedCopies`, called at `:373`) runs `removeManagedPath` on every host destination in the backup metadata. The occupied-unowned guard (`:139-143`) checks only the canonical path.
- **Trigger:** `install sigmawrite --destination .agents/skills --destination .claude/skills --copy`. Edit both copies, then run `uninstall --all --yes`, which makes a backup. Now create your own `.claude/skills/sigmawrite/MINE.md`, and run `restore --skill sigmawrite --yes`.
- **Result:** the command exits 0, and `MINE.md` is deleted with no backup.
- **Fix:** in `classifyRestoreSkill`, block with `occupied-unowned` for any copy destination that exists and is not owned.

### A4. P2 · M1: legacy migration takes another tool's `.agents/state.json` or `.agents/backups/` and then blocks every command
- **Where:** `src/state.js:13-20` (`LEGACY_ENTRIES`), `:77-87`, and `:98-151`. Any entry with one of these names counts as Sigma state. The entry is moved and the original is deleted, with no check of its content.
- **Trigger:** `.agents/state.json` = `{"other":"tool"}` and `.agents/backups/mine.txt`. Run `install sigmawrite`.
- **Result:** both entries are gone from `.agents/`. Install exits 1 with `invalid project state: missing or invalid schemaVersion`, and every later command fails the same way.
- **Fix:** parse the legacy `state.json` first. Migrate only when it is valid Sigma state (`schemaVersion` and `scope`). Otherwise leave everything where it is.

### A5. P2 · M2: migration error sends users to a version that fails in the same place
- **Where:** `src/state.js:120` says `npx @djordje-stojanovic/sigmaskills@0.4.0 uninstall --all --yes`. But the new layout already ships in 0.4.0 (`git show v0.4.0:src/state.js`, `PRIVATE_STATE_DIRNAME`). The old layout is 0.3.0 and older (`git show v0.3.0:src/state.js`). The comments at `src/state.js:12`, `:90`, `:123` repeat the same wrong version, and `docs/installer.md:139,143` does too.
- **Fix:** use `@0.3.0` and "0.3.0 and older" in the code, the comments, and the doc.

### A6. P2 · M1: `install` reports success for an owned link that points to the wrong target
- **Where:** `src/adoption.js:215-224` returns `adoptable: true` for `sigmaOwned && isLink` and does not check `inspected.wrongTarget`. Then `src/destinations.js:475` skips the wrong-target check at `:479`.
- **Trigger:** `install sigmawrite --destination .claude/skills`, then point the junction at another folder, then install again.
- **Result:** the output says `✔ Installed … [junction]` with exit 0, but the link still points to the other folder. `status` says `wrong-target`.
- **Fix:** return kind `wrong-target` (not adoptable) and repair it or stop.

### A7. P2 · M1: `status` and `update`/`uninstall` disagree about a link a user added inside a skill
- **Where:** `src/status.js:59-92` skips symlinks. `src/update.js:81-88` (`inventorySkillTree`) counts them. There are two `walkLiveFiles` copies, and they have drifted apart.
- **Trigger:** add a junction inside `.agents/skills/sigmawrite/`.
- **Result:** `status` says `Drift: No / clean`. `update --dry-run` says `local-only`. `uninstall --all` treats the skill as clean and removes it with no backup.
- **Fix:** use one shared live-tree walker.

### A8. P2 · M1: replace or export of a link destination always fails with EEXIST
- **Where:** `src/backup.js:249-270` (`copyTreeNoFollow`) creates `destDir` first, then tries `symlinkSync` to that same path. Callers are `commitSkillBackup` (`:278`) and `exportSkillTree` (`:372`).
- **Trigger:** an unowned junction to a changed Sigma-looking folder at `.claude/skills/sigmawrite`, then `install sigmawrite --destination .claude/skills --adopt-unverified export` (`replace` fails the same way).
- **Result:** `EEXIST: file already exists, symlink …`. It fails closed, but `skip` is the only choice that works.
- **Fix:** when the source is a link, do not create `destDir` first, or copy the resolved tree.

### A9. P3 · M1: a newer-schema Sigma lock is downgraded and stripped
- **Where:** `src/project-lock.js:68` accepts any `schemaVersion >= 1`. `saveProjectLock` keeps only `release`, `skills`, and `revision`.
- **Fix:** reject a `schemaVersion` above `PROJECT_LOCK_SCHEMA_VERSION`, as `src/state.js:246` already does for state.

### A10. P3 · M1: the replace path changes customization bytes (breaks ADR 0001 "byte-for-byte")
- **Where:** `src/transaction.js:419-433` uses `injectCustomContent`. `validateCustomizationBlock` (`src/customization.js:59-63`) strips one leading newline, and `:337` adds back `\n`.
- **Result:** the block `"\r\nmy rule\r\nsecond\r\n"` becomes `"\nmy rule\r\nsecond\r\n"`.
- **Fix:** use `rawCustomContent` with `injectRawCustomContent`, as the update path already does.

### A11. P3 · M1: the path containment helper rejects valid names that start with `..`
- **Where:** `startsWith('..')` in `src/destinations.js:153,226`, `src/links.js:29`, `src/backup.js:25`, `src/status.js:173`. `resolveSkillPath(root, '..cache/skills', 's')` throws "escapes the project".
- **Fix:** use one helper: `rel === '..' || rel.startsWith('..' + path.sep) || path.isAbsolute(rel)`.

### A12. P3 · M2: smaller installer items
- `src/transaction.js:225-226,609-610`: the SIGINT/SIGTERM rollback handlers are added and removed inside one synchronous call, so they can never run. Remove them, or add real crash recovery for `.sigma-staging` and `-backup-` leftovers.
- `src/transaction.js:127`: the lock is taken before code that can throw (`:141-158`) and outside the `try/finally` that releases it.
- `src/concurrency-lock.js:15-26`: a hard kill between `mkdir` and `rmdir` leaves `.sigma.lock.guard`, and every later run then fails with `lock-busy`. This is documented, but it is not detected.
- `src/update.js:570-731`: a failure on skill N throws away the result report for skills already updated.
- Dead code: `MIGRATABLE_KINDS` (`src/adoption.js:354`, no users). `src/interactive.js:346` removes a `keypress` listener from `stdin`, but the listener is on `this.parser`.
- `src/interactive.js:137` counts `CI=false` and `CI=0` as CI, while `src/cli.js:276` does not. Use one rule.

## B. Release and registry scripts (scripts/)

### B1. P3 · M1: `applyReleaseIdentities` corrupts the changelog when notes contain `$'`, `` $` ``, or `$&`, and it skips a lone `## [Unreleased]`
- **Where:** `scripts/release.js:154-165` and `:167-182` pass a string, not a function, as the `replace` value. The lookahead needs a following `## [`.
- **Fix:** use `() => text`, and accept end of file in the lookahead.

### B2. P3 · M2: the changelog compare links are never maintained
- `writeReleaseIdentities` (`scripts/release.js:155-176`) rewrites the headings but not the link list. This is the root cause of C1.

### B3. P3 · M1: the auto-merge gate fails open when inputs are missing (latent)
- **Where:** `scripts/registry/automation.js:116-124`. Each check runs only when its input is present. A call with no `headSha`, `checkConclusion`, or `classification` returns `autoAuthorized: true` with `merge` and `publishNpm` on. Today `registry-sync.yml` always sets the inputs.
- **Fix:** deny when any required input is missing or is not a 40-hex SHA.

### B4. P3 · M2: registry automation treats errors as "nothing there"
- `scripts/registry/automation-ci.js:190-198` (`hasConcurrentRun` → `false` on error), `:84-104` (`npmVersions` / `githubVersions` → `[]` on any error), and `:323-326` (`acquireVersionLock` is not a real lock).
- **Fix:** tell a 404 apart from other errors, and rethrow the others.

### B5. P3 · M2: dead or misleading sync paths
- `scripts/registry/sync.js:134,182-186`: `fetchPinnedSourceSync` always throws.
- `:195`: `runSync` overwrites the fixture even with `--dry-run`.
- `scripts/registry/validate.js:29-48` accepts destinations under `.git/hooks`, `.github/workflows`, and `.ssh` as a "safe addition". Add a denylist.
