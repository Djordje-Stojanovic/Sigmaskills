# Delivery: design, interface, performance, accessibility

Plain text read as written (a markdown file, a message) gets item 2 only, as a read-through; write the rest "not needed: plain text". Items 2 to 4 and 7 apply to screens and media; a print file gets items 1, 5 and 6, checked on a printed or PDF proof.

1. **One design file before the first screen.** Colour, type, spacing and components as tokens; light and dark. Use the project's existing design file when it has one, else an installed design skill (for example `impeccable` or `frontend-design`), else write the tokens yourself. Check: every screen uses only the tokens.
2. **The learner's path.** The first sitting ends with one real task done. Every screen shows where the learner is, how far they are against the end lines, the one next action and where to get help. The learner can reach any finished part, leave, and resume with a recap of what the next part needs. Answers open after the learner commits. Check: walk one learner from the first page to the last proof task with no dead end.
3. **Phone and desktop.** The layout works at the narrowest and widest screens the learner uses, by touch and by keyboard. Check: screenshots at both widths, no sideways scroll, no hidden action.
4. **A performance budget, written before the build.** Three numbers from the learner's slowest device and network (the grill asks): time until the first lesson is readable or playable, the weight of a page, the start time of a video. Check: measure each page type in the built course (Lighthouse or the browser's own tools); a miss is a defect. To climb a missed budget, SigmaClimb.
5. **Accessibility to WCAG 2.2 AA.** Contrast, readable text size, keyboard use, visible focus, alt text, captions and a transcript for every video and audio, reduced motion honoured. Check: an automatic checker (axe or the browser's own) with zero errors, plus one pass by keyboard only.
6. **Taste.** SigmaTaste on the first screen, chart, film or deck of each kind; act on its top items. Load a chart skill before any chart, and a video tool such as HyperFrames for video, when installed.
7. **Check the real thing.** Open the rendered course in a browser, play the media, read the console. Check: zero console errors, every page and media file loads, and the screenshots go into the review. A check that reads only source files does not count.
