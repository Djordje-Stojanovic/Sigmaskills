# Interface words

## What it sees

Words inside the design: buttons, labels, headings, empty states, errors, toasts, captions, slide titles. They are design content, not decoration. Each one says what a thing is or what happens next, in the user's words, and keeps the same name through the whole flow.

## Tells

- Buttons that say "Submit", "Continue", "Learn more", "Get started", "Click here".
- System words in the interface: "webhook config", "entity", "payload", where the user thinks "notifications".
- The action changes name mid-flow: "Publish" button, "Saved" toast.
- Small labels above headings that add a layer and no information.
- Errors that apologise or stay vague; empty screens with no next action.
- Headlines that sell instead of saying what the thing is.
- Slide titles that name a topic ("Q3 results") instead of the point ("Q3 revenue grew 18 %").

## Fix moves

- Name every action by its result: "Save changes", "Send invoice", "Export CSV". Keep the verb through the flow.
- Rename things in the user's vocabulary; keep one word per concept.
- Errors: what happened, then how to fix it. Empty states: what goes here, and the button that puts it there.
- Cut labels that add no information.
- Slide and chart titles state the point in a short sentence.
- Sentence case and plain verbs, unless the brand's own style says otherwise.

## Verify

- Read only the buttons and headings in order: the flow should make sense from them alone.
- List each action name and its toast or result: the words match.
