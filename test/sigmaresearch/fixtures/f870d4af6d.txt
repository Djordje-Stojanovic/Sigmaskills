You would want to use multiprocessing for <a href=\"https://en.wikipedia.org/wiki/CPU-bound\" rel=\"noreferrer\">CPU-bound</a> tasks. An example would be trying to calculate a sum of all elements of a huge list. If your machine has 8 cores, you can &quot;cut&quot; the list into 8 smaller lists and calculate the sum of each of those lists separately on separate core and then just add up those numbers. Imagine a program that sends lots of HTTP requests to the web. If you used a single-threaded program, it would stop the execution (block) at each request, wait for a response, and then continue once received a response. The problem here is that your CPU isn't really doing work while waiting for some external server to do the job; it could have actually done some useful work in the meantime! The fix is to use threads - you can create many of them, each responsible for requesting some content from the web. The nice thing about threads is that, even if they run on one CPU, the CPU from time to time &quot;freezes&quot; the execution of one thread and jumps to executing the other one (it's called context switching and it happens constantly at non-deterministic intervals).
